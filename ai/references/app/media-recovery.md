# Durable Resolve media recovery

Use these commands on a saved native project. Inspect the active native project and Resolve project before operations. They do not replay a send.

1. `resolve.media.inspect {}` starts background file/hash and current Resolve reference inspection. Poll `resolve.media.status {}` until `pending=false`; read `report`, `error`, unknown outcomes and reference scope. Legacy projects can inspect references before a package exists.
2. `resolve.media.manage {action:"select", options:{pool_ids:[...]}}` selects exact inspected media IDs for the UI. `action:"page", options:{index:0}` changes the reference-list page. These are view state, not document edits.
3. Plan consolidation with `resolve.media.manage {action:"consolidate", options:{pool_ids:[...]}, execute:false}`. It accepts 1–128 explicit IDs, copies verified immutable files using content-addressed directories and retains basenames for RelinkClips. Poll status, review the exact files/IDs/placement, then repeat the exact options with `execute:true`. Original files stay.
4. Plan project relocation with `resolve.media.manage {action:"move", options:{destination:"C:/work/New.carverproj"}, execute:false}`. Save current edits first. A matching reviewed plan can be applied with `execute:true`. Existing destinations are refused. The project and media are staged/verified; partial commits are reported. Open the resulting project, check IDs/preview/save-reopen, then separately review Resolve relinking. Originals are retained for reference-aware cleanup.
5. `resolve.media.relink {destination:"C:/work/New Media", execute:false}` plans against existing matching destination hashes. Poll/review, then apply the same destination with `execute:true`. Native revision, project/root, Resolve project ID and manifest fingerprint are guarded. Read-back checks paths and timeline identity/placement; verify save/reopen persistence for the actual Resolve project.
6. `resolve.media.manage {action:"cleanup", options:{}, execute:false}` gives a consequence list. Current-project and manifest inventory cannot certify references in other Resolve projects. Incomplete coverage retains files and refuses execution; do not treat an unlisted current-project reference as proof that a file is unused.

The status command returns its data in the MCP receipt's `readings` array. Keep partial/unknown results, including results for an original native project if the user changed context during the job. Never retry uncertain mutations blindly. Media operation journals preserve original transfer receipts and record verified project-specific relocation history. Missing, changed, damaged or unsupported manifests remain visible.

Verification: native integration 12 checks, offline package/consolidation/move/recovery cases, and scratch Resolve audio/carrier save-reopen tests. Carrier testing proves tool inventory retention; it does not certify every Fusion input or connection. Cleanup across all Resolve projects remains an explicit unsupported proof boundary.

Rendered sequence delivery: the bridge uses the documented percent-padded frame pattern and exclusive source endpoint, then verifies item ID, kind, track, start and duration. Acknowledgement without matching read-back is partial/unknown, not success. Native sequence+mixdown default-host delivery and save/reopen were witnessed on this PC in Resolve Studio21.1; this does not qualify other editions/machines.
